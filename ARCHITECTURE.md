# Архитектура tg-event

CLI остаётся `python -m tg_event.cli`: команды `collect`, `parse`, `run`, `watch`, `serve`, `cleanup` и их параметры сохранены. Python использует стандартную библиотеку и Telethon; админка — Vue 3, Pinia и Vuestic UI. Настройки моделей OpenRouter остаются в существующем `Settings`, рефакторинг их не меняет.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `cli.py` | Разбор аргументов, загрузка настроек и запуск выбранной команды. |
| `collector.py` | Чтение Telegram, первая загрузка канала, получение отслеживаемых правок и сведения об успешности чтения. |
| `pipeline.py` | Сбор в JSONL, разбор пакета с ограниченным параллелизмом, подготовка и проверка сопоставлений, сохранение пакета. |
| `watcher.py` | Цикл и восстановление сбора, фильтрация версий, лимиты, профили прогресса, JSON-копия, совместный запуск с ботом и расписание очистки. |
| `openrouter_parser.py`, `event_schema.py` | HTTP-вызов модели, промпты, проверка ответа и правила публикации нового извлечения. |
| `database.py` | Существующая схема SQLite, запросы, атомарная запись пакета и прогресса, ручные изменения и объединение. |
| `event_updates.py`, `source_policy.py` | Применение изменений по времени и доверию к источнику, сохранение ручных полей, выбор основной ссылки. |
| `channels.py` | Настройки каналов, нормализация имён, границы первой загрузки и состояние проверок. |
| `admin.py`, `admin_service.py`, `auth.py` | HTTP и статика; подготовка прикладных команд; токены и ограничение попыток входа. |
| `bot.py` | Периоды по часовому поясу города, выборка опубликованных событий и форматирование Telegram-ответов. |
| `cleanup.py`, `storage.py` | Очистка с резервной копией; формат отладочных JSONL и сырых сообщений. |

Разделение не вводит контейнер зависимостей, общий диспетчер команд, ORM или новый формат данных. SQL остаётся явным; существующие сессии, таблицы, ID и связи сохраняются.

## Обработка пакета

1. Watcher читает включённые каналы и прогресс своего полного пути `--state` из SQLite. Старый JSON импортируется только при создании профиля.
2. Collector читает ранние непройденные сообщения порцией и отдельно получает отслеживаемые посты. Первоначальные границы recent-канала фиксируются один раз.
3. Watcher исключает сохранённые неизменённые и устаревшие версии, затем применяет лимиты разбора. Необработанный разрыв нельзя перепрыгнуть.
4. `pipeline.parse_rows` держит не более трёх задач. Результаты возвращаются в порядке входных постов, даже если запросы завершились иначе. Пустой текст не отправляется модели. Один пост даёт список из нуля, одного или нескольких событий.
5. `pipeline.save_to_database` сортирует успешные посты по времени версии, готовит кандидатов и проверяет результат одного запроса сопоставления на пакет. При отсутствии событий, а также для единственного события без кандидатов, запроса сопоставления нет. Модель и резервная попытка извлечения не изменены.
6. `database.save_parsed_rows` сохраняет весь пакет, связи и извлечения, применяет изменения и ручные ограничения, отсеивает только новые прошедшие карточки, выбирает основную ссылку и продвигает прогресс одной транзакцией.
7. После фиксации SQLite watcher записывает отладочный JSONL и атомарную JSON-копию прогресса. Успешный цикл может запустить еженедельную очистку.

Сопоставление с LLM выполняется до транзакции записи: сетевое ожидание не удерживает блокировку записи SQLite. Если выбранная карточка исчезла перед сохранением, запись пакета завершается ошибкой и прогресс не продвигается.

## Админка и ручные операции

В рабочем HTTP-сервере каждый запрос к базе получает собственное соединение и закрывает его после операции, включая ошибку. Инициализация при старте завершается до запуска HTTP-потоков. Вход, проверка токена и статика не требуют соединения с SQLite. Для существующих тестовых фикстур `make_handler` также принимает готовое соединение; обращения к нему сериализуются блокировкой, чтобы запросы не смешивали транзакции.

`admin_service.prepare_event_update` нормализует поля формы и проверяет допустимые типы; функции обновления и объединения вызывают операции базы. HTTP-обработчик отвечает за маршрут, авторизацию, чтение JSON и перевод ожидаемых ошибок в прежний формат ответа. Некорректные объекты, enum-контейнеры, идентификаторы вне диапазона SQLite и повреждённые токены получают 4xx.

Ручное обновление и объединение получают блокировку записи до чтения состояния карточек. Проверка версии конфликта, запись полей и ручных блокировок относятся к одной транзакции. Другое соединение не может сменить проверяемый конфликт между чтением и записью.

Сохранение извлечения и разрешение менять карточку разделены: отвергнутое или устаревшее уточнение остаётся связанным источником, но не дополняет поля карточки. Известный приоритет исходного подтверждённого источника сохраняется при правке текста без повторения имени организатора; такая правка не продлевает `last_change_at` или срок хранения карточки.

## Ошибки и повторный запуск

- В watcher ошибка одного разбора не отменяет успешно разобранные посты. Позиция доходит только до первой необработанной версии в полученной порции. При повторе уже сохранённые неизменённые посты не требуют LLM.
- `parse`/`run` прерывают пакет при фатальной ошибке. После её обнаружения новые задачи не запускаются; уже начавшиеся запросы могут закончиться, отменить сетевой вызов внутри потока нельзя.
- SQL-сбой, в том числе при продвижении позиции в конце пакета, откатывает карточки, источники, ручные связи и прогресс вместе.
- Ошибка JSON-экспорта после commit не откатывает SQLite. Следующий цикл восстанавливается по базе и не разбирает успешно сохранённые посты заново.
- Первая загрузка продолжается сразу при успешном продвижении; ошибка или отсутствие прогресса возвращают обычную паузу. `--once` выполняет одну порцию и сообщает о частичном сбое после сохранения успешных результатов.
- Cleanup имеет SQL-транзакцию, но файлы и SQLite не образуют общую транзакцию. Порядок резервирования и удаления сохранён; детали — в этапе 9 `PLAN.md`.

## Проверки

```bash
python3 -m unittest discover -s tests
```

Набор использует временные базы и подмены Telegram/LLM. HTTP-проверкам нужен локальный loopback-порт. `tests/test_cli.py` проверяет команды и передачу параметров, `test_pipeline.py` — порядок, ограничение задач, ошибки и несколько событий из поста. Интеграционные тесты watcher проверяют повтор после разрыва, SQL-откат и сбой JSON-копии.

Из `admin-ui`:

```bash
npm test
npm run build
```

Frontend-проверки выполняются стандартным Node test runner (Node 22+), на реальных Pinia store и скомпилированном script setup с подменённым API. Флаг VM modules нужен только тестам; новых зависимостей нет. Они проверяют поздние ответы фильтров и сохранение пустой категории через обычную форму и закрытие конфликта.

Живое качество Telegram/LLM, работа VPS и HTTPS не подтверждаются этими локальными проверками. Одновременные watcher одного профиля по-прежнему не поддерживаются проверенным контрактом. Ручная календарная валидация и форматирование ранее сохранённых некорректных дат требуют отдельного решения; рефакторинг не меняет допустимые ручные значения дат.

## Ручная проверка без рабочих данных

После `npm run build` в `admin-ui` запустить из корня репозитория:

```bash
PYTHONPATH=tests python3 - <<'PY'
from contextlib import closing
from pathlib import Path
from tempfile import TemporaryDirectory

from test_admin import default_settings, parsed_row
from tg_event.admin import serve
from tg_event.database import connect_database, init_database, save_parsed_row

with TemporaryDirectory(prefix="tg-event-review-") as folder:
    settings = default_settings(
        database_path=Path(folder) / "review.sqlite3",
        admin_static_dir=Path("admin-ui/dist").resolve(),
        admin_user="demo", admin_password="demo-local", admin_secret="demo-only",
    )
    with closing(connect_database(settings.database_path)) as db:
        init_database(db)
        row = parsed_row()
        row["events"][0]["category"] = None
        save_parsed_row(db, row)
    serve(settings, host="127.0.0.1", port=18081, dev=False)
PY
```

Открыть `http://127.0.0.1:18081`, войти как `demo` / `demo-local`. Проверить сохранение названия карточки без категории и после очистки категории, переключение фильтров, добавление и паузу тестового канала, выход и закрытый API без авторизации. Для гонки фильтров можно включить замедление сети в инструментах разработчика браузера.

Этот запуск напрямую создаёт тестовые настройки, не читает env и не запускает watcher, Telegram или LLM. Добавление канала только создаёт запись во временной базе. Остановить сервер `Ctrl+C`; временная база удалится. Конфликты, отмены дайджестов и восстановление после сбоев дополнительно проверяются автоматическими сценариями, перечисленными выше.
